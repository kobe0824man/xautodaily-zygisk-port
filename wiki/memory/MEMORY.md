## Facts
- API 82's `XposedBridge` declares exactly ten native methods (getStartClassName, getRuntime, startsSystemServer, getXposedVersion, initNative, hookMethodNative, invokeOriginalMethodNative, setObjectClassNative, dumpObjectNative, cloneToSubclassNative). The JNI table in `source/app/src/main/cpp/zygisk_hook.cpp` must match them exactly — `RegisterNatives` rejects the whole table otherwise, which kills `JNI_OnLoad`. ⛔ Never register an API method that API 82 does not declare.
- `:xposed-api82-stubs` holds compile-only stubs for the hidden framework APIs the upstream API 82 sources reference and is consumed with `compileOnly`, so it never reaches the APK.
- The platform's background sync rewrites the working tree and silently reverts uncommitted edits. Commit small changes immediately instead of batching them.
- The published de.robv.android.xposed:api:82 artifact is a compile-time stub: every method body throws RuntimeException("Stub!") and only getXposedVersion is native, so a frameworkless runtime (the Zygisk payload) must vendor the upstream API 82 sources. #constraint #xposed #zygisk (mcp, 2026-11-25)
- XAutoDaily Zygisk port work lives on branch zygisk-port-3.1.0-rc6 of productos-agents/productos-xautodaily-zygisk-port-4f7949f5; main carries the upstream sources plus platform edits. #project #repo (mcp, 2026-11-25)
- Source-level verification for the port runs via source/zygisk/tests/verify_local_port.sh with JAVA_HOME and ANDROID_JAR; it compiles the port package and vendored API 82, runs the unit tests, and checks the JNI table, vendored provenance, OpenSSL archives and packaging refusals. #workflow #verification (mcp, 2026-11-25)
- GitHub Actions cannot start any job for the productos-agents organisation: every run fails in under two seconds with no runner, no steps and an empty log, including a trivial self-check workflow; the repository owner must resolve the org Actions billing/quota. #constraint #ci (mcp, 2026-11-25)
